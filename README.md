# SAP B1 - Calculadora de Requisitos

Calculadora HTML de una sola página (sin dependencias de servidor) para dimensionar hardware de SAP Business One 10 — App Server, DB Server (SQL Server o HANA) y PC de usuario — según Feature Package, tipo de despliegue, usuarios, add-ons y arquitectura de conexión cliente.

Archivos vivos (desde v3.0 la parte visual y la funcional van separadas):

- [`index.html`](./index.html): estructura de la página (pantalla de bienvenida, panel de configuración, barra de acciones, formulario del informe). No tiene estilos ni lógica adentro.
- [`styles.css`](./styles.css): toda la parte visual (colores, tipografía, móvil, formulario del informe, impresión de la pantalla). Cambiar aquí no altera ningún cálculo.
- [`app.js`](./app.js): toda la parte funcional. Secciones, en orden: STATE (estado), FP DEFINITIONS, PLATFORM MATRICES (`SW_SQL` / `SW_HANA`), CALC (fórmulas de App Server, SQL y HANA), HELPERS, RENDER (arma los resultados), CONTROLS (botones del panel), BIENVENIDA (v3.0, solo navegación), INFORME EN WORD (v3.1 y v3.2: arma el texto con las cifras de la calculadora y las tablas de soporte y licencias de Microsoft, y genera el .docx sin librerías), formulario del informe e INIT.

Regla del proyecto: las fórmulas y matrices de `app.js` son las que funcionan y solo se cambian cuando Ghost lo pide.
- [`pruebas.html`](./pruebas.html): prueba automática. Abre la calculadora, corre 6 casos fijos (SQL y HANA, nueva y actualización, App Server y PC de usuario), 8 textos y 24 pruebas del informe (cifras, nombre de archivo, escape del texto, secciones opcionales, .docx, servidores según el despliegue, versión de SQL a instalar, licencias de Microsoft), 38 en total, y dice PASA o FALLA. Abrirla después de cualquier cambio (en GitHub Pages: `.../pruebas.html`; en local, con un servidor como `py -m http.server`). Los valores esperados solo se cambian cuando Ghost aprueba un cambio de fórmula.
- `?v=3.2` en los enlaces a `styles.css` y `app.js` dentro de `index.html`: se sube en cada versión para que el navegador no mezcle el HTML nuevo con un CSS o JS viejo guardado en caché.

## Cómo se usa (v3.2)

1. Bienvenida, paso 1: elegir el motor (Microsoft SQL Server o SAP HANA).
2. Bienvenida, paso 2: elegir Instalación nueva o Actualización.
3. Se abre la calculadora con esa selección ya hecha; el resto (Feature Package, despliegue, conexión, usuarios, add-ons, tamaño de BD) se ajusta en el panel. El botón "← Inicio" vuelve a la bienvenida.
4. "Generar informe" abre un formulario: Nombre del cliente (obligatorio; es también a quien va dirigido el informe), Fecha de revisión (viene con la de hoy), Tiempo de la actividad (opcional, texto libre con su unidad, por ejemplo "1 hora"), Participantes (al menos uno: nombre, cargo y empresa) y, opcionales, Consideraciones y Compromisos (una por línea). Los servidores (virtualizados o físicos) ya no se piden: salen del tipo de despliegue elegido en la calculadora (Virtualizado → virtualizados; On-Premise → físicos; Citrix/WTS → físicos con Citrix/WTS). "Descargar Word" baja un .docx solo de texto con el formato "Informe de revisión": 1. Información del Cliente (con la arquitectura de BD: en SQL Server, la versión a instalar, que es la más reciente que soporta el Feature Package, por ejemplo SQL Server 2022 para SP 2605), 2. Participantes, 3. Objetivo, 4. Actividades (servidor de base de datos y servidor de aplicaciones con RAM, almacenamiento y procesador, más observaciones), 5. Resultado y, si se llenaron, 6. Consideraciones y 7. Compromisos. Las observaciones incluyen el estado de licencias y soporte de Microsoft para el SQL Server y el Windows Server elegidos (tablas SQL_FIN, WS_FIN y LIC_FECHA en app.js; consulta del 2026-11-09, se actualizan a mano cuando se vuelva a consultar). Todas las cifras salen de la calculadora; el mismo informe sirve para instalación nueva y actualización (cambian el objetivo y las observaciones). En línea, en vivo: **https://contactosheinsohn2023-svg.github.io/sap-b1-calculadora-requisitos/**

## Aprendizaje general reutilizable: tooltips cortados por overflow del contenedor padre

**Síntoma:** un tooltip o menú posicionado con `position:absolute` dentro de un contenedor que tiene `overflow-y:auto` (o `scroll`) aparece cortado en un borde, aunque el contenedor no tenga `overflow-x` declarado.

**Causa raíz:** en CSS, si se declara solo `overflow-y` con un valor distinto de `visible`, el navegador computa `overflow-x` como `auto` automáticamente (así lo exige la spec). Eso convierte al contenedor en un "clipping ancestor" en ambos ejes, y cualquier descendiente `position:absolute` que se salga del borde horizontal queda recortado, aunque visualmente el contenedor solo parezca scrollear verticalmente.

**Solución:** cambiar el elemento flotante a `position:fixed` (así escapa del overflow clipping de los ancestros) y calcular su posición en JS con `getBoundingClientRect()` del elemento que lo dispara, en un handler `onmouseenter` (o focus):
- Centrar horizontalmente respecto al ícono/trigger, pero con `Math.max`/`Math.min` para no salirse de los bordes del viewport.
- Decidir arriba/abajo según el espacio disponible (si no cabe arriba, mostrarlo abajo), con una clase CSS (`tip-above` / `tip-below`) que mueve también la flechita del tooltip.
- Guardar la posición de la flecha como variable CSS (`--arrow-left`) para que no quede descentrada al clamear el tooltip contra el borde.

**Condición para que funcione:** `position:fixed` solo escapa la clipping del ancestro si ningún ancestro tiene `transform`, `filter`, `will-change` o `perspective` distinto de `none` (esas propiedades crean su propio "containing block" y vuelven a atrapar el `fixed`). Verificar eso antes de aplicar la solución.

**Dónde más puede aparecer:** cualquier UI con paneles laterales scrolleables (listas, formularios largos) que tengan tooltips, dropdowns custom o menús contextuales flotantes — es un patrón común en dashboards y formularios de configuración, no solo en esta calculadora.

**Caso donde apareció:** tooltip de ayuda del ícono ⓘ "Buffer Pool" en el panel lateral de esta calculadora (panel con `.main{overflow-y:auto}`). Antes de la corrección, el tooltip aparecía cortado del lado izquierdo (texto empezando a mitad de palabra).
